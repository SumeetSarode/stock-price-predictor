Getting your API keys

The app needs two free API keys to run its LLM agents — one from Groq, one from Google (Gemini). No credit card, no payment. Start to finish this takes about three minutes.

What you need at a glance

KeyNeeded?CostGet it from
GEMINI_API_KEY Recommended Free tier Google AI Studio
MISTRAL_API_KEY Recommended Free tier Mistral console
NVIDIA_NIM_API_KEY Optional Free tier NVIDIA build
GROQ_API_KEY Optional Free tier Groq Console
OPENROUTER_API_KEY Optional Free tier OpenRouter
ALPHA_VANTAGE_API_KEY Optional Free tier Alpha Vantage
STOOQ_API_KEY Optional Free (captcha) Stooq
Every key is optional. Each one switches on that provider's models in the fallback chain; a blank key just means those models are skipped (a logged warning, never a crash). Two providers need no key at all — OVH's free endpoint and the local Ollama model — so the app still runs with every key blank. More keys = more fallback models when one provider is busy: Gemini + Mistral is the recommended minimum. Groq and OpenRouter are not in the default chain (no model of theirs passed the 2026-11-02 sweep); keep them only for custom chains. The last two keys power price-data providers that are not in the default chain (see Optional keys).

Why a fallback chain?

The LLM agents run on a fallback chain of 27 free hosted models plus a local Ollama model last. Every one passed both prediction steps in every run of the 2026-11-02 off-VPN sweep. They are ordered fastest first, with providers alternating so that when one provider's free quota runs out, the next hop lands in a fresh quota bucket.

CHAIN_AGENTIC = gemini/gemini-3.5-flash-lite → mistral/ministral-3b-latest → gemini/gemini-flash-lite-latest → … → nvidia_nim/… → ovhcloud/… → ollama_chat/qwen3:8b

1. Gemini key (Google AI Studio)

  1. Go to aistudio.google.com/app/apikey.
  2. Sign in with any Google account.
  3. Click Create API key. If prompted, let it create a new Google Cloud project for you (the default is fine) or pick an existing one.
  4. Copy the key — it starts with AIza…. This is the value for GEMINI_API_KEY.
The key is shown in full only once at creation but you can re-open it from the same page any time. Treat it like a password.

2. Mistral key (Mistral console)

  1. Go to console.mistral.ai/api-keys and sign in.
  2. If asked for a plan, choose the free Experiment plan.
  3. Click Create new key and copy it. This is the value for MISTRAL_API_KEY.

Optional, same idea: an NVIDIA key from build.nvidia.com (Get API Key, starts with nvapi-) goes in NVIDIA_NIM_API_KEY.

3. OpenRouter key (optional, custom chains only)

  1. Go to openrouter.ai/settings/keys.
  2. Sign in (Google / GitHub / email — no card required for the free tier).
  3. Click Create Key, give it any name.
  4. Copy the key — it starts with sk-or-.... This is the value for OPENROUTER_API_KEY.
No OpenRouter model is in the default chain. Add this key only if you put an openrouter/* model into CHAIN_AGENTIC yourself; while it is blank, such entries are skipped.

4. Where to paste them

The app reads keys from a file called .env in the project root. A fresh clone doesn't have one (it's deliberately excluded from git), so create it by copying the template:

cp .env.example .env

Then open .env in any text editor and paste each key you have after its = sign. Leave the others blank — those models are skipped:

GEMINI_API_KEY=AIza...your_actual_key...
MISTRAL_API_KEY=...your_actual_key...
NVIDIA_NIM_API_KEY= # blank = skipped
No quotes, no spaces around the =. Save the file. That's it — the app picks the keys up on its next start.

5. Free-tier limits (good to know)

The free tiers are generous enough for personal use. When one provider says “slow down”, the app simply moves on to the next model in the chain:

ProviderFree-tier limit (approx., set by the provider)
Gemini~10 requests/min, ~250/day per Google project (the app paces itself under this)
Mistral (Experiment plan)rate-limited per minute; no card needed
NVIDIA NIMdeveloper-tier rate limits; no card needed
OVH (no key)~2 requests/min per model

Sharing a key with other tools? If the same Gemini key is also used by another app, lower GEMINI_RPM in .env so the two don't fight over the same quota.

6. Optional keys (you probably don't need these)

These power price-data providers that are not in the default chain. Leave them blank unless you have a specific reason:

KeyWhen you'd want it
ALPHA_VANTAGE_API_KEY Only if you manually add alpha_vantage back to PRICE_CHAIN. Free tier is just 25 requests/day and its NSE feed is unreliable — omitted by default.
STOOQ_API_KEY Only if you fetch non-Indian tickers (US/EU/JP). Stooq has no NSE coverage, so it's useless for Indian equities.
Price data itself needs no key for the default setup — jugaad, nse_bhavcopy, and yfinance are all key-free.

Keeping your keys safe

  • .env is gitignored — it never gets committed or pushed. Keep it that way.
  • Never paste a key into chat, screenshots, or a public repo. If one leaks, delete it in the provider console and create a fresh one.
  • The keys live only on your machine — this app runs entirely locally.

How to know it worked

Start the app and run a prediction on any stock. If the keys are wired correctly, you'll get a full prediction card. If a key is missing or wrong, you'll see a clear error message when you click Predict (the UI itself still boots fine — keys are only needed at prediction time).
