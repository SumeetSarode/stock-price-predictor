News analysis

Headlines without context are a footgun. An LLM sub-agent reads actual article bodies, frames expectations against analyst estimates, and emits a structured assessment with cited sources.

Why a sub-agent and not just "shove headlines into the prompt"

To get this right we need a reader that can:

  • Decide which news is material vs. noise.
  • Read article bodies — not just titles.
  • Compare expectations vs. reality (analyst estimates as the baseline).
  • Cross-check with corporate filings and recent price action.
  • Output a structured, bounded assessment, not a free-form essay.

Hence a dedicated Pydantic-AI sub-agent with four tools and a strict output schema.

The four tools the news agent can call

The agent decides which tools to call and in what order. It's a reasoning loop, not a fixed pipeline:

ToolWhat it returns
fetch_news(ticker, days_back=7) List of news articles (title, URL, published-at, source) — no body yet.
fetch_article_body(url) Extracted clean body text for one article (or an error status). Called only for headlines the agent decides are material.
fetch_filings(ticker, days_back=30) NSE corporate announcements (insider trades, board meetings, results).
fetch_estimates(ticker) Analyst-estimate snapshot (EPS/revenue forecasts, recommendation counts, price-target distribution).
get_recent_price_action(ticker, days=10) Tiny internal helper: { open, close, pct_change_total, max_drawdown_intra, days_up, days_down } over the last 10 sessions.

What the news agent emits: the ImpactAssessment

FieldTypeWhat it means
directionbullish / bearish / neutralThe net directional read across all news + filings + estimates.
magnitudelow / medium / highHow much should this shift the synthesizer's confidence? Not raw price magnitude.
confidencefloat [0, 1]How sure the agent is of its own read.
summarystringOne paragraph of plain English digest.
catalyststuple of Catalyst objectsUp to 5. Each has: title, source URL, published-at, importance, why_it_matters.
riskstuple of Risk objectsSame shape — things that cut against the direction call.
articles_consideredintHow many article bodies the agent actually read.
filings_consideredintHow many filings the agent considered.
Catalysts and risks carry the source URL explicitly. The downstream citation guardrail (see Quality Controls page) will reject the whole prediction if the synthesizer cites a URL that doesn't appear here.

The rules the news agent's prompt enforces

1. Materiality filter

Material — keepNon-material — drop
Earnings, M&A, regulatory action, management change, large insider trades, guidance changes. Sector op-eds, generic market commentary, "stock down 2% on no news" stories.

2. Already-priced-in adjustment

If a story's price impact has already played out in the last 10 days (per the price-action tool), the agent must downgrade that headline's importance and explicitly note "already absorbed" in the why_it_matters field.

Story: "Reliance announces ₹75,000-cr capex plan." Published 8 days ago. Stock is already up 9% in those 8 days. Verdict: bullish news, but mark importance LOW and add "already absorbed in last week's rally" — so the synthesizer doesn't double-count.

3. Expectation framing

For earnings, the agent compares reported figures against analyst-estimate consensus, not against the prior period.

EPS came in at ₹28.40 — 5% growth year-over-year. Bearish if estimates expected 12% growth. Bullish if estimates expected 3%. Same number, opposite read.

4. Catalyst quota

  • Hard cap: at most 5 catalysts AND at most 5 risks. Forces prioritisation.
  • Minimum floor: if the agent emits bullish or bearish, at least one catalyst must be present. Without one, the call must be neutral. Enforced by both the prompt and the schema validator.

5. Confidence calibration guidance

RangeWhen to use it
0.00 – 0.30Weak signal, mostly noise.
0.40 – 0.60Moderate signal, multiple sources agree.
0.70 – 0.85Strong signal, with a clear specific catalyst.
> 0.85Avoid. Reserved for "smoking gun" cases only.

6. Hallucination guardrails (baked into the prompt)

  • Every catalyst / risk MUST quote a specific URL the agent actually fetched. Inventing sources is forbidden.
  • If fetch_news returns zero articles, the agent returns direction=neutral, magnitude=low, confidence=0.0 with empty catalyst/risk tuples and a summary that says so explicitly.
  • If every fetch_article_body call returns status=error, same zero-result behaviour.

The resilient LLM chain

The news agent runs on an ordered list of LLM providers. If one fails (rate limit, schema-validation failure, network) it cools down for 60 seconds and the request falls through to the next:

  1. Gemini 2.5 Flash (primary)
  2. Groq Llama 3.3 70B (first fallback — extremely low latency)
  3. OpenRouter Mistral Large (final fallback)

The model that actually produced the assessment is recorded in the prediction's model_chain field, so an auditor can see which provider was responsible.

What if the whole news layer fails?

We degrade gracefully, not fail-fast. The system substitutes a sentinel ImpactAssessment:

direction = neutral
magnitude = low
confidence = 0.0
summary = "news pipeline unavailable"
catalysts = () , risks = ()

The prediction is tagged news_impact:degraded in model_chain so consumers can filter. The synthesizer naturally weights technicals more heavily because the news side contributes nothing either way. Per the calibration guardrail, predictions with this tag are capped at confidence ≤ 0.65 — we can't claim high confidence on a partial input.
