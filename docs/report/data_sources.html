Data we ingest

Predictions are only as good as their inputs. Here is every external source the system reads from, what we keep, what we deliberately throw away, and what happens when a source fails.

1. Price bars (OHLCV, daily)

For one ticker we fetch about two calendar years of daily bars (≈ 520 trading sessions). Each bar carries the five numbers every chartist already knows:

FieldMeaning
OpenFirst traded price of the session (NSE: 09:15 IST).
HighHighest price touched during the session.
LowLowest price touched during the session.
CloseFinal traded price (NSE: 15:30 IST).
VolumeTotal number of shares traded that session.

Where the bars come from (fallback chain)

We try three providers in order. If one fails for a transient reason (rate limit, timeout, empty result) we mark it asleep for 60 seconds and try the next:

  1. yfinance — primary. Yahoo Finance's free OHLCV feed.
  2. Stooq — fallback. Polish data provider that mirrors most global tickers.
  3. Alpha Vantage — final fallback. Requires an API key. Used when both above fail.
If every provider has failed in the last 60 seconds, we drop the cooldown and try them all anyway — better to risk a duplicate rate-limit call than to deny the user an answer with cached data clearly available somewhere.

Why two years of bars?

Several indicators need long history before their math stabilises. The biggest offender is the Average Directional Index (ADX): it is "doubly smoothed" by Wilder's averaging, which means the starting bias only decays below 1% after about 10 × length = 140 bars. Add the 200-bar SMA and a 60-bar squeeze lookback and you need roughly 400 trading days before every number on the page is meaningful. Fetching 520 gives us comfortable headroom.

In-memory cache

One process-wide cache, keyed by ticker. The first cluster tool that asks for HDFCBANK fetches it once; the other three clusters read from cache. Across-ticker requests run in parallel; same-ticker requests share one fetch via a per-ticker lock. The cache holds the widest date range ever fetched, so narrower requests are pure slices.

2. News headlines (GDELT)

What is GDELT? The Global Database of Events, Language and Tone — a non-profit project that indexes news media worldwide in near-real-time. We query its "Doc API 2.0" endpoint, which exposes a rolling 7-day index of stories.

What we keepWhat we drop
Title, URL, published timestamp (converted to IST for display), source domain, language. GDELT's pre-computed tone score and its themes taxonomy. We let the LLM read the article itself instead of trusting a third party's sentiment guess.

Two-step fetch

  1. Discovery (fetch_news): ask GDELT for all articles about ticker X in the last 1–7 days. Get back a list of metadata only (no article body).
  2. Extraction (fetch_article_body): for the headlines the LLM decides are material, fetch the article URL and extract clean text using trafilatura (a Python library that strips ads, nav bars, related-article rails).
Extraction failure is normal at scale (paywalls, JavaScript-only sites, bot blocks). We surface those as "status=error" data rather than throwing exceptions. The LLM is told to ignore them and re-prioritise from the remaining material articles.

Language

English-only by default (sourcelang:eng). This is a real limitation — a leak in a Marathi business newspaper may move HDFCBANK 2% intraday and we never see it. Adding Hindi / Marathi feeds is on the Phase-2 backlog.

3. NSE corporate filings

The same "Corporate Information → Announcements" feed that powers NSE's public website. This is the source for things that aren't press releases yet but absolutely move price:

  • Insider trades — promoter buys/sells, often a leading indicator.
  • Board-meeting notices — typically scheduled 7–14 days before earnings.
  • Result publications — the actual quarterly numbers when they drop.
  • Regulatory disclosures — SEBI inquiries, related-party transactions.
⚠️ Fragility note. This is not a public API. It is the same internal endpoint that NSE's own website calls via JavaScript. We have to prime cookies, forge browser headers, and handle Cloudflare challenges. NSE can (and does) silently change the contract — when they do, this layer goes down until someone notices and patches it.

4. Analyst estimates

Pulled from yfinance's analyst snapshot. Per ticker we keep:

CategoryFields
Earnings forecasts EPS for current quarter, next quarter, current year, next year.
Revenue forecasts Same four buckets.
Recommendations Count of Strong-Buy Buy Hold Sell Strong-Sell calls.
Price targets Low / median / mean / high across all analyst targets.
Why this matters: the news LLM uses the estimates as the expectations baseline. A 5% EPS growth is bullish if estimates expected 3%, but bearish if estimates expected 12%. Without estimates, the LLM has no way to interpret "beat" or "miss".

Limitation: yfinance gives us a snapshot only, not a time-series. We cannot detect "estimates raised by 8% over the past week" — which is itself a powerful catalyst type. Adding a historical-estimates source is on the Phase-2 list.

5. Recent price action (internal helper)

A small derived feed (no external API) that summarises the last 10 trading days into one structured object:

{ open, close, pct_change_total, max_drawdown_intra, days_up, days_down }

The news LLM uses this for the already-priced-in check. If a "beat-and-raise" story dropped a week ago and the stock already ran 6%, the catalyst's forward impact is discounted — the news layer must say "absorbed" rather than "bullish".

6. India VIX (market regime)

NSE's implied-volatility index — the market's "fear gauge", one free daily number that summarises expected 30-day volatility. Fetched via yfinance under the symbol ^INDIAVIX (we deliberately avoid the GPL-licensed nsepython for a single number).

We use India VIX as a regime gate, never a direction signal. A bullish setup in a high-vol regime deserves smaller size / wider stops; the same setup in a low-vol regime is cleaner. The gate is self-calibrating: we compare the latest value to its own rolling median — above 1.15× = high_vol, below 0.85× = low_vol, otherwise normal. Absolute VIX levels drift across market epochs, so a percentile-style comparison beats any magic constant.

7. Point-in-time news (Wayback Machine)

Used only during honest backtests. For a fair replay, the news the model reads at a past as_of date must be the news that actually existed on or before that date — never a later revision written with hindsight. Fetching the live URL today would leak the future.

So we query the Internet Archive's Wayback CDX API for the most recent snapshot at/before as_of, then extract clean text with trafilatura.

Hard guarantee. We never return content from a snapshot captured after as_of. The query is bounded server-side and re-checked client-side. If no qualifying snapshot exists we return nothing — we do not silently fall back to the live page, because that would reintroduce the exact look-ahead bias we are eliminating.

What happens when a source fails

If this fails…We do this
Price bars (all three providers) Abort the prediction. No technicals = no anchor. The user gets a clear error.
News (GDELT down or returns empty) Degrade gracefully. We synthesize a "neutral, confidence=0, no catalysts" placeholder and tag the prediction with news_impact:degraded so the user knows.
Filings (NSE rejecting our scraping) Surface as "no filings considered". News LLM continues with what it has.
Estimates (yfinance snapshot missing) Surface as missing. News LLM continues but cannot do beat-vs-miss framing.
